## Findings this run (pipeline bugs / gaps, not content problems)

1. **`fetch-texts.mjs`'s `wittenberg` selector cannot handle plain-text Wittenberg sources.**
   `german-mass-luther`'s source is a `.txt` file. Cheerio-parsing raw text with no HTML tags
   collapses all whitespace (including blank lines) per the HTML spec, so the whole ~23KB document
   becomes a single markdown block instead of many paragraph blocks. `stripChrome()`'s
   `wittenberg-contact-block` rule then correctly finds the real contact-footer text buried in that
   one block, and because block-kind rules drop the entire matching block, deletes the whole
   document — confirmed by a 0-char output. This will also break `life-and-acts-of-luther-melanchthon`
   (`.txt`, same source type) whenever it's attempted. Needs a code fix — a `wittenberg-txt` source
   variant that reflows on the raw text's blank lines before cheerio/turndown, or wraps the fetched
   text in `<pre>` before parsing — filed as a finding, not fixed in this content-only run.
2. **No Wikisource ruleset exists yet in `scripts/lib/source-chrome.mjs`.** Three of this run's four
   Wikisource fetches leaked real chrome into the written markdown: a "needs standardizing"
   maintenance banner, stray `//thumb.wikimedia.org/...` image links (relative-protocol URLs that
   won't resolve off-site — the `relative-image` advisory already catches these, it just doesn't
   strip them), a `Layout N` proofread-page artifact, and the trailing "Public domain / Retrieved
   from" footer. All hand-cleaned this run (same treatment as New Advent's chrome tells before
   `source-chrome.mjs` existed for that source). Worth a `SOURCE_SELECTORS.wikisource` chrome pass
   and matching `source-chrome.mjs` rules in a future PR, on the same model as the New Advent and
   Wittenberg ones.
3. **Two more Reference-URL mis-transcriptions found**, in addition to the six the 2026-09-21 run
   already flagged in the existing `pending` queue: Wikisource disambiguation pages for
   `the-apostles-creed-church` (fixed by re-sourcing) and `thirty-nine-articles-of-religion-al`
   (fixed by finding the direct page). `invocavit-sermons-luther`'s Gutenberg URL was also stale
   (404) and needed the volume-level page plus a manual excerpt of just the one sermon requested.
   This continues to look like the same class of problem the 2026-09-14/09-21 logs raised — worth
   the wider spot-check of the remaining ~100 `pending` entries those logs recommended, whenever
   there's a session to spare for it.
